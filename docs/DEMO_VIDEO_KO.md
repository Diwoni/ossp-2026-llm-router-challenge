# 3분 시연 영상 대본과 촬영 체크리스트

## 영상의 목적

시연 영상은 긴 학습 과정을 다시 돌리는 장면이 아니다. 심사자가 3분 안에 다음을
확인하도록 구성한다.

1. 입력 프롬프트만 보고 모델을 선택한다.
2. 세 등급에서 비용 안전 정책이 다르다.
3. 제출 Docker 이미지가 네트워크 없이 실제 JSON을 만든다.
4. 점수·비용·결정성·라이선스 근거가 저장소에 남아 있다.

## 촬영 전 준비

- 화면 해상도는 1920×1080, 브라우저 확대는 110~125%를 권장한다.
- 알림, 메신저, 개인 토큰과 다른 브라우저 탭을 닫는다.
- 터미널 글자 크기를 키우고 저장소 루트에서 시작한다.
- 최종 이미지를 미리 받아 둔다. 영상 중 469MB 다운로드 시간은 보여 주지 않는다.
- `scripts/demo_method4.sh balanced`를 한 번 미리 실행해 로컬 환경을 확인한다.
- 영상 URL은 비로그인 창에서 재생되는 공개 또는 링크 공개 상태로 둔다.

## 3분 타임라인

### 0:00~0:20 — 문제와 한 줄 해답

화면: GitHub README의 제목과 `심사자를 위한 60초 요약`.

내레이션:

> 같은 질문이라도 경량 모델로 충분한 경우와 추론 모델이 필요한 경우가 있습니다.
> 저희 라우터는 답을 생성하지 않고 질문 내용만 보고 세 모델 중 하나를 고릅니다.
> 목표는 정해진 비용 안에서 전체 정답 점수를 최대화하는 것입니다.

### 0:20~0:50 — 최종 구조

화면: README의 Mermaid 흐름도와 등급별 안전계수 표.

내레이션:

> 파인튜닝한 multilingual E5가 질문의 의미를 읽고, 길이·코드·수식 특징과 비슷한
> 공개 문제의 성적을 함께 봅니다. 개발할 때는 Qwen 임베딩을 교사로 사용했지만,
> 최종 컨테이너에는 22KB 학생 계수만 들어갑니다. 마지막 배분기는 질문을 하나씩
> 독립 선택하지 않고 전체 비용 제한을 보며 비싼 모델을 배정합니다.

### 0:50~1:20 — 과적합을 줄인 의사결정

화면: `docs/FINAL_EXPERIMENT_REPORT_KO.md`의 채택·기각 표와 안전계수 sweep.

내레이션:

> 공개 Dev 재대입 최고 숫자는 0.7176이었지만 비용 스트레스 네 개를 실패해
> 버렸습니다. 최종 0.7164 후보는 공개 점수가 조금 낮아도 문제군과 비용을 흔든
> 228개 시나리오를 모두 통과했습니다. Qwen 학생 보정도 한 번의 Dev가 아니라
> 일곱 개 교차검증에서 모두 양수인 경우만 채택했습니다.

### 1:20~2:10 — Docker 실동작

화면: 터미널 전체 화면. 다음 명령을 실행한다.

```console
scripts/demo_method4.sh balanced
```

내레이션:

> 지금 최종 ARM64 이미지에 네트워크 없음, 읽기 전용 파일 시스템, 2 CPU,
> 2GiB 메모리, PID 32 제한을 적용했습니다. 입력은 공식 toy 프롬프트이고,
> 컨테이너는 model_id 선택 JSON 하나만 만듭니다.

스크립트가 출력한 `선택 문항 수`, 모델별 선택 수, 첫 세 결정을 보여 준다.

> 실제 평가처럼 답변 내용이나 outcomes 파일은 컨테이너에 전달하지 않았습니다.
> 입력 episode가 빠지거나 추가되지 않았고 스키마 검증도 통과했습니다.

### 2:10~2:40 — 실행·결정성·공급망 증거

화면: `docs/CONTAINER_VERIFICATION_KO.md`의 반복 실행 표와 SBOM 구간.

내레이션:

> 공개 Train과 Dev 2,640문항 전체는 등급별 두 번씩 90초 안에 통과했고, 최악은
> 64.1초였습니다. 입력 순서를 완전히 뒤집어도 모델 선택 불일치는 0개입니다.
> 모델 자산은 Release 압축과 파일별 SHA를 이중 확인하며 SPDX SBOM과 라이선스
> 고지를 함께 제공합니다.

### 2:40~3:00 — 오픈소스 개발 과정과 마무리

화면: GitHub Issues와 PR 목록을 짧게 보여 준 뒤 README로 돌아온다.

내레이션:

> 기준선, 후보 실험, 비용 안전성, Docker, 문서를 한국어 이슈와 PR로 나눴고,
> 실패한 실험도 수치와 이유를 남겼습니다. 이 프로젝트의 핵심은 공개 점수 하나가
> 아니라 의미 이해, 비용 강건성, ARM64 재현성을 모두 갖춘 라우터입니다.

## 실동작 명령이 실패할 때

- Docker가 꺼져 있으면 Colima 또는 Docker Desktop을 먼저 시작한다.
- 이미지가 없으면 GHCR 공개 전환 뒤 전체 digest로 pull한다.
- Apple Silicon이 아니면 `linux/arm64` 에뮬레이션 때문에 시간이 더 걸릴 수 있다.
- 영상에서 실패를 숨기기보다 원인을 고친 뒤 처음부터 다시 촬영한다.

## 제출 전 영상 확인

- [ ] 길이 3분 이내
- [ ] 저장소 URL과 프로젝트명이 읽힘
- [ ] 개인 토큰·이메일·로컬 사용자 경로 노출 없음
- [ ] Docker 명령의 네트워크 차단·자원 제한이 보임
- [ ] 실제 출력 JSON과 모델별 선택 수가 보임
- [ ] 공개 재대입 점수를 숨은 예상 점수라고 말하지 않음
- [ ] 링크를 로그아웃 창에서 재생 가능
- [ ] 결과보고서의 영상 URL과 실제 URL이 일치
