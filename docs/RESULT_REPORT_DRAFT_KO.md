# 공식 결과보고서용 5페이지 원고

> 공식 Word/HWP 양식을 받은 뒤 아래 내용을 해당 칸에 옮긴다. `[입력 필요]`
> 자리표시자는 제출 전에 모두 교체하고, 양식의 첫 쪽 작성 안내와 회색 안내 문구를
> 삭제한다. 이 파일 자체를 대회 사이트에 제출하지 않는다.

## 기본 정보

- 부문: 지정과제형 — SK텔레콤 Efficient LLM Routing Challenge
- 프로젝트명: 예산 강건형 의미 기반 LLM 라우터
- 팀명: `[입력 필요: 접수 시스템의 정확한 팀명]`
- 접수번호: `[입력 필요]`
- 프로젝트 등록 URL: `[최종 커밋 후 전체 SHA 스냅샷 URL 입력]`
- 시연 영상 URL: `[입력 필요]`
- 주 라이선스: Apache-2.0

## 1페이지 — 과제 이해와 목표

LLM 서비스는 모든 요청을 가장 큰 모델에 보내면 품질은 높아질 수 있지만 비용과
지연이 급격히 증가한다. 반대로 모든 요청을 경량 모델에 보내면 저렴하지만 복잡한
수학·코드·긴 문맥 문제의 품질이 떨어진다. 본 프로젝트는 프롬프트 내용만 보고
`ax31-light`, `ax31`, `axk1-think` 중 하나를 선택하여 세 비용 등급에서 품질을
최대화하는 라우터를 개발한다.

운영자는 모델별 과거 정답 점수와 토큰 사용량을 공개 Train 1,760문항, Dev
880문항에 제공한다. 실제 평가 컨테이너에는 질문만 들어오며 정답, 모델 답변,
데이터셋 이름, 문항별 결과는 주어지지 않는다. 따라서 라우터는 질문의 의미와
표면 특징에서 모델별 예상 품질·비용을 추정해야 한다.

본 프로젝트의 목표는 공개 Dev 재대입 점수만 높이는 것이 아니다. Fast 1.25,
Balanced 2.0, Premium 4.0 비용 한도를 숨은 분포에서도 지키고, linux/arm64,
2CPU, 2GiB, 등급당 90초, 네트워크·GPU 없는 환경에서 결정적으로 실행되며,
모델 자산과 라이선스를 제3자가 재현할 수 있어야 한다.

핵심 차별점은 다음과 같다.

1. 쉬움/어려움 단일 분류가 아닌 세 모델별 예상 품질과 비용의 공동 예측
2. E5 의미 표현, 내용 특징, 실제 유사 문제 성적, 잔차 보정의 하이브리드 구조
3. Qwen 임베딩을 오프라인 교사로 사용하고 22KB 학생으로 증류
4. 문항별 독립 분류가 아닌 전체 배치 비용 최적화
5. 최고 재대입 후보를 버리고 228개 비용 스트레스를 통과한 안전 정책 채택

권장 그림: README의 `최종 라우팅 흐름`.

## 2페이지 — 기술 설계

### 파인튜닝 E5

MIT 라이선스의 `intfloat/multilingual-e5-small`을 사용한다. 공개 Train의 세
모델별 score와 log 비용, 모델 간 순서·차이를 동시에 학습했다. 마지막 인코더
블록 1개와 160차원 투영 head를 2 epoch 학습하며 seed는 20260819로 고정했다.
긴 프롬프트의 마지막 질문·선택지·코드 assert를 보존하기 위해 토큰 공간의 44%를
앞, 56%를 뒤에서 취한다.

### 내용 특징과 KNN

글자·단어·문장 수, 한글·영문·숫자 비율, 코드·수학·추론 표지, 객관식 여부,
긴 문맥 여부 등 20개 내용 특징을 사용한다. ID, split, 입력 위치는 쓰지 않는다.
KNN은 새 질문과 가까운 공개 질문의 실제 모델별 성적을 거리 가중 평균한다.
2회·4회 생성으로 생기는 이산 score의 잡음을 직접 회귀 하나에만 맡기지 않기
위함이다.

### Qwen 교사-학생과 등급별 정책

Apache-2.0의 `Qwen3-Embedding-0.6B`은 개발 중 공개 프롬프트 표현을 만드는
오프라인 교사다. Qwen 판단을 E5 160차원과 내용 특징 20개로 예측하는 Ridge
학생에게 증류했다. 최종 이미지에는 Qwen 가중치와 외부 호출이 없다.

- Fast: 파인튜닝 E5 KNN, think 금지, 안전계수 0.95
- Balanced: E5 KNN + Qwen 학생 + 잔차, 안전계수 0.90
- Premium: hash 80% + 80토큰 동결 E5 20%, 안전계수 0.78

배분기는 예상 품질 이득에서 비용 패널티를 뺀 값을 기준으로 이진 탐색하여 전체
배치가 안전 예산 안에 들도록 모델을 선택한다.

## 3페이지 — 실험과 검증

공식 hash-regex 공개 Dev 기준선은 0.695369318182, Train-only E5는
0.706846590909였다. 최종 공개 전체 자산의 Dev 재대입은 0.716420454545지만,
Dev outcome이 최종 자산에 포함됐으므로 숨은 평가 예측치가 아니라 패키징 회귀
검사로만 사용한다.

Qwen 학생 후보는 고정 설정으로 공식 3-fold, 층화 5-fold, 내용 군집 5-fold와
세 seed를 조합한 7개 검증에서 Balanced 변화가 모두 양수였다. 실제 비용비는
1.740896~1.769289로 제한 2.0 아래였다.

경쟁 포크의 GLM·GBM·문제군 전문가·비용 상한 아이디어를 독립 재구현했다.
앙상블 후보는 Train OOF를 0.6765909091에서 0.6802130682로 높였지만 고정 후
Dev는 0.7006534091에서 0.6977840909로 하락했다. 문제군 Premium 전문가는
Dev 하락과 비용 4.099 초과가 함께 발생했다. 검증되지 않은 복잡성은 제거했다.

Premium 안전계수 0.84는 공개 Dev 재대입 0.717613636364였지만 228개 스트레스
중 4개에서 예산을 넘었다. 안전계수 0.78은 공개 재대입이 0.716420454545로
0.001193182 감소했지만 228개를 모두 통과하고 최악 비용비 3.973534를 확보했다.

권장 표: `FINAL_EXPERIMENT_REPORT_KO.md`의 안전계수 선택 표.

## 4페이지 — 실행 완성도와 재현성

최종 컨테이너는 linux/arm64, 숫자 UID/GID 65532, 읽기 전용 rootfs, 네트워크
없음, 2CPU, 2GiB, PID 32 조건에서 실행한다. PyTorch, transformers,
scikit-learn, scipy는 이미지에 없다. ONNX Runtime, tokenizers, NumPy와 내보낸
계수만 사용한다.

공개 Train+Dev 2,640문항을 세 등급 각각 2회 실행한 결과 Fast 49.583/49.705초,
Balanced 50.183/50.598초, Premium 64.061/63.943초로 90초를 통과했다. 반복별
출력 SHA가 같고, 입력을 완전히 뒤집어도 세 등급의 누락·추가·model_id 불일치가
모두 0이었다.

모델 자산 10개 636,519,519바이트는 GitHub Release로 배포한다. 다운로드 시
376,520,961바이트 압축 파일의 SHA-256을 먼저 확인하고 압축 해제 뒤 파일별
크기와 SHA를 다시 확인한다. SPDX 2.3 SBOM에는 Debian 105개, Python 6개,
모델 2개를 기록한다.

최종 이미지 digest:
`ghcr.io/diwoni/ossp-2026-llm-router-challenge@sha256:1913d548e33fe9fcad60eac4e33c73142c73e0b3b1754061080c941154b63829`

권장 표: `CONTAINER_VERIFICATION_KO.md`의 공식 자원 제한 반복 결과.

## 5페이지 — 오픈소스 운영과 발전 가능성

자체 코드·문서는 Apache-2.0, E5는 MIT, Qwen은 Apache-2.0이다. 기반 이미지와
모델 원본 리비전, 원본·변환 파일 SHA, THIRD_PARTY_NOTICES, SPDX SBOM을 함께
공개하여 코드뿐 아니라 실행 자산의 공급망을 추적할 수 있다.

개발은 8개 한국어 이슈로 기반, 검증, E5 기준선, 경쟁 후보, 최종 라우터, 비용
강건성, Docker·Release, 제출 문서를 나눴다. 각 단계는 별도 브랜치와 PR #9부터
#15 이상으로 검토하고, 기능·검증·문서를 논리 단위 한국어 커밋으로 남겼다.
성공한 결과만 정리하지 않고 GLM, GBM, 문제군 전문가, 강제 상한의 실패 수치와
기각 이유를 보존했다.

향후에는 다음 방향으로 발전할 수 있다.

1. 새로운 공개 평가 모델을 manifest 기반 adapter로 추가
2. 더 작은 다국어 인코더와 정적 양자화 비교
3. 비용 예측의 conformal upper bound와 온라인 drift 경보
4. 공개 문제군 밖에서도 적용 가능한 의미 군집 기반 안전 예산
5. 라우팅 결과의 설명 가능성 및 운영 대시보드

본 프로젝트는 특정 세 모델에 맞춘 한 번의 대회 코드에 그치지 않고, 품질 예측기,
비용 예측기, 등급 정책, 배분기, 실행 프로토콜을 분리했다. 따라서 공개 모델과
비용 정책을 교체해도 같은 검증·SBOM·컨테이너 절차를 재사용할 수 있다.

## AI 활용과 라이선스 기재 문안

- AI 모델 활용: multilingual-e5-small을 공개 outcome으로 파인튜닝하고,
  Qwen3-Embedding-0.6B을 공개 프롬프트의 오프라인 교사로 사용하여 학생 head를
  학습함. 최종 실행 중 외부 AI 호출과 Qwen 가중치 사용 없음.
- AI 코딩 도구 활용: `[입력 필요: 팀이 실제 사용한 도구와 사용 범위]`. 생성된
  코드는 팀이 실행·검토하고 테스트와 GitHub 이력으로 검증함.
- 모델·코드 라이선스: 자체 코드 Apache-2.0, E5 MIT, Qwen Apache-2.0. 세부
  리비전·SHA·NOTICE는 저장소 공개 문서와 SBOM에 포함.
