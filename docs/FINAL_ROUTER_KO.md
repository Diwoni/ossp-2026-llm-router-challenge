# 최종 하이브리드 라우터 설계와 학습 절차

## 결론

우리가 최종 채택한 방법은 하나의 거대한 분류기가 아니다. 공개 문제에서 학습한
경량 E5 의미 표현, 문제의 겉모양을 보는 특징, 비슷한 문제 검색, 작은 잔차 모델,
Qwen 오프라인 교사를 모방한 학생, 비용 제한 배분기를 등급별로 다르게 조합한다.

핵심 목표는 “어려운 질문인가?”라는 한 값을 맞히는 것이 아니라, 각 입력에 대해
다음 두 값을 세 모델별로 추정하는 것이다.

1. 이 모델을 골랐을 때 얻을 예상 정답 점수
2. 이 모델을 골랐을 때 쓸 예상 비용

그다음 입력 전체를 함께 보며 Fast·Balanced·Premium 예산 안에서 예상 정답 점수의
합이 가장 커지도록 모델을 고른다.

## 입력부터 출력까지

```text
프롬프트 내용
  │
  ├─ 파인튜닝 E5 INT8 ───────────────┐
  ├─ 20개 길이·문자·수식·코드 특징 ──┼─ 품질 차이·비용 예측
  ├─ hash-regex 기준 모델 ───────────┤
  └─ 공개 문제 KNN·Qwen 학생 ────────┘
                                      │
                         등급별 신호 혼합·반올림
                                      │
                    비용 안전계수를 적용한 배치 최적화
                                      │
                 episode_id별 model_id만 원래 순서로 출력
```

라우터는 모델 답변을 생성하지 않는다. 프롬프트만 보고 `ax31-light`, `ax31`,
`axk1-think` 중 하나를 선택한다.

## 1단계: E5 인코더 파인튜닝

### 원본

- 모델: `intfloat/multilingual-e5-small`
- 리비전: `d1d99a1efae6779390caba937d92c54b5bc70e51`
- 라이선스: MIT
- 원본 가중치 SHA-256:
  `1a55775f53449dac10a2bcbc312469fac40b96d53198c407081a831f81c98477`

### 입력 처리

긴 문제의 끝에는 질문·선택지·코드의 `assert`가 자주 있으므로 앞에서 128토큰만
자르지 않는다. 사용할 토큰 공간의 44%는 앞부분, 56%는 뒷부분에 배정한다.
여기에 다음과 같은 내용 기반 특징 20개를 붙인다.

- 글자·단어·문장·메시지 수
- 한글·영문·숫자·공백 비율
- 코드·수학·추론·제약 표지 수
- 객관식 여부, 목록·URL·물음표·줄바꿈 수
- 2천 자·8천 자 이상 긴 문맥 여부

`episode_id`나 입력 위치는 특징으로 사용하지 않는다.

### 학습 설정

| 항목 | 값 |
| --- | ---: |
| 공개 Train 행 | 1,760 |
| epoch | 2 |
| 마지막 인코더 block 학습 | 1개 |
| 새 projection 크기 | 160 |
| dropout | 0.15 |
| 인코더 학습률 | 0.00002 |
| head 학습률 | 0.0007 |
| weight decay | 0.02 |
| seed | 20260819 |

학습 정답은 단순한 `쉬움/어려움`이 아니다. 세 모델 각각의 공개 `score`와 log
비용을 동시에 사용한다. 손실 함수는 품질 오차, 비용 오차, 가장 좋은 모델의 순서,
모델 간 품질 차이, 비용의 단조성을 함께 본다. 이렇게 해야 `ax31-light보다 ax31이
얼마나 더 좋은가`처럼 실제 선택에 필요한 차이를 배운다.

3-fold OOF로 학습하지 않은 행의 예측을 만들고 안전계수를 정한 뒤, 공개 Train
전체로 최종 E5를 다시 학습했다. 마지막에는 PyTorch 모델을 ARM64 CPU에서 실행할
수 있는 INT8 ONNX로 변환했다.

## 2단계: 공개 문제 KNN

`KNN`은 새 질문과 가장 비슷한 공개 질문 여러 개를 찾고, 그 문제들에서 세 모델이
어땠는지 가중 평균하는 방법이다. 가까운 문제일수록 더 큰 가중치를 준다.

- Fast·Balanced: 파인튜닝 E5의 160차원 라우터 공간, 이웃 10개
- Premium: 동결 E5의 384차원 의미 공간, 이웃 20개
- 공개 자료에서 추정한 문제군이 같으면 Fast에만 작은 가산점 0.03

직접 점수 회귀 하나만 믿지 않고 비슷한 실제 문제의 상대 성적을 다시 보는 이유는
데이터가 2회·4회 생성의 이산 정답률이라 작은 표본 잡음이 크기 때문이다.

## 3단계: 잔차 head와 Qwen 학생

### 잔차 head

E5 예측과 hash-regex 예측, 20개 내용 특징을 합친 36개 입력으로 작은 ExtraTrees와
Ridge가 모델 간 품질 차이와 비용을 보정한다. 최종 실행에서는 scikit-learn을
설치하지 않고, 학습된 트리와 계수만 JSON으로 내보내 NumPy로 계산한다.

### Qwen 교사-학생

- 교사: `Qwen/Qwen3-Embedding-0.6B`
- 리비전: `97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3`
- 라이선스: Apache-2.0
- 원본 가중치 SHA-256:
  `0437e45c94563b09e13cb7a64478fc406947a93cb34a7e05870fc8dcd48e23fd`

Qwen은 공개 Train·Dev 프롬프트를 표현하는 오프라인 교사로만 사용했다. Qwen의
판단을 파인튜닝 E5 160차원과 문제 특징 20개를 입력으로 받는 Ridge 학생에게
증류했다. 최종 이미지에는 Qwen 가중치나 외부 호출이 없고 22,894바이트 계수만
있다.

Balanced에서 학생 출력 75%를 E5 KNN 의미 점수에 섞고, 이 의미 신호와 잔차
신호를 50:50으로 합친다. 고정 후보는 7종 교차검증에서 모두 작은 양수였고 실제
비용비가 1.74~1.77로 제한 2.0 아래였다. 세부 수치는
[`CANDIDATE_EXPERIMENTS_KO.md`](CANDIDATE_EXPERIMENTS_KO.md)에 있다.

## 4단계: 등급별 정책

| 등급 | 품질 신호 | 허용 모델 | 안전계수 |
| --- | --- | --- | ---: |
| Fast | 파인튜닝 E5 KNN | light, ax31 | 0.95 |
| Balanced | E5 KNN + Qwen 학생 + 잔차 | 세 모델 | 0.90 |
| Premium | hash 80% + 80토큰 동결 E5 20% | 세 모델 | 0.78 |

Fast는 비용 폭발 위험이 큰 `axk1-think`를 아예 후보에서 제거한다. Premium은
품질을 더 올릴 수 있어도 비용 한도 4.0을 딱 채우지 않는다. 공개 결과에서 안전
0.948 후보는 비용 3.980867까지 올라 작은 분포 변화로 등급 전체가 0점이 될 수
있어 기각했다.

배분기는 각 입력을 독립적으로 먼저 점수화하지만 최종 선택은 전체 배치의 비용
합을 보고 한다. 예상 이득에서 비용에 비례한 값을 빼는 기준을 이진 탐색해 제한
안에서 가장 이득이 큰 입력에 비싼 모델을 배정한다.

## 결정성과 누수 방지

- 프롬프트 내용과 메시지 수로 먼저 정렬해 ONNX batch를 항상 같게 만든다.
- 모든 선택 점수를 소수점 넷째 자리로 반올림한다.
- 마지막에만 원래 입력 순서로 되돌린다.
- ID, 입력 위치, outcomes 파일은 실행 특징으로 사용하지 않는다.
- 같은 입력의 반복 실행과 역순 입력에서 episode별 선택이 같아야 한다.
- 실행 중 네트워크·GPU·Qwen·PyTorch·transformers·scikit-learn을 사용하지 않는다.

## 고정 자산

[`method4-assets.manifest.v1.json`](../artifacts/method4-assets.manifest.v1.json)에
최종 10개 파일, 총 636,519,519바이트의 크기와 SHA-256을 기록했다. 가장 큰 파일은
80토큰 동결 E5 FP32 ONNX 470,248,414바이트이고, 파인튜닝 E5 INT8 ONNX는
118,428,041바이트다.

Release에서 자산을 받은 뒤 다음처럼 검증한다.

```console
PYTHONPATH=src:. python3 tools/verify_method4_assets.py \
  --assets-dir build/final-assets/method4
```

로컬 실행은 다음과 같다.

```console
METHOD4_FINAL_ASSETS=build/final-assets/method4 \
  scripts/run_final_router.sh \
  data/materialized/dev/inputs.json balanced build/submission/balanced.json
```

| 수치 | 뜻 |

| 0.717613636364 | Premium 안전 0.84 연구 후보의 공개 Dev 재대입 값; 비용 스트레스 실패로 기각 |
| 0.716420454545 | Premium 안전 0.78 최종 후보의 공개 Dev 재대입 패키징 검사 |

0.7176은 숨은 평가 예측치가 아니다. Dev outcome이 최종 검색 기준과 학생 head에
들어갔기 때문이다. 최종 우승 가능성은 재대입 최대 숫자보다 여러 분할의 방향,
예산 여유, 공식 컨테이너 실행 성공, 재현 가능한 자산과 문서의 신뢰도를 함께 본다.
