# 실험 및 채택 규약

## 실험 전에 기록할 내용

모든 후보는 코드를 합치기 전에 다음 내용을 이슈 또는 실험 보고서에 적습니다.

1. **가설**: 무엇을 바꾸면 왜 좋아질 것으로 보는가?
2. **대조군**: 어떤 고정 후보와 비교하는가?
3. **변경 변수**: 동시에 바꾸는 요소는 무엇인가?
4. **평가 분할**: 학습, 후보 선택, 마지막 확인에 어떤 자료를 쓰는가?
5. **채택 기준**: 어느 수치가 어느 정도 좋아져야 하는가?
6. **위험**: 데이터 누수, 비용 초과, 실행 시간, 라이선스 위험은 무엇인가?

## 공통 평가표

각 실험 보고서는 최소한 다음 값을 포함합니다.

- Train→Dev 가중 종합 점수와 세 등급별 품질·비용
- Dev→Train 가중 종합 점수와 세 등급별 품질·비용
- 문제군 Group K-fold 평균, 표준편차, 최솟값
- 비용 스트레스 시나리오 수와 예산 초과 횟수
- 공개 전체 재대입 점수
- 전체 2,640문항의 세 등급 실행 시간
- 반복 실행 결정성 및 ID·순서 변경 감사 결과

## 채택 문턱

다음 조건을 모두 만족해야 최종 후보에 반영할 수 있습니다.

1. 누수 없는 검증 평균이 대조군보다 개선되거나, 같은 수준에서 최악 fold와
   비용 안전성이 분명히 개선되어야 합니다.
2. 특정 한 분할만 좋아지고 역방향 또는 문제군 검증이 크게 나빠지면 기각합니다.
3. 모든 비용 스트레스 시나리오에서 세 등급 예산을 통과해야 합니다.
4. 공식 자원 제한에서 90초 이내에 충분한 여유를 두고 끝나야 합니다.
5. 제출 이미지에 포함한 코드·모델·학습 파일의 출처와 라이선스를 설명할 수
   있어야 합니다.

공개 전체 재대입 점수만 오른 후보는 최종 후보가 아니라 `공개 적합 실험`으로
표시합니다. 반대로 작은 평균 차이가 반복 fold에서 안정적으로 나타나면 실제
일반화 개선 후보로 봅니다.

## 결과 상태

| 상태 | 뜻 |
| --- | --- |
| `채택` | 모든 문턱을 통과하여 최종 라우터에 반영 |
| `조건부 채택` | 특정 등급 또는 보정기만 독립적으로 반영 |
| `보류` | 신호는 있으나 분산이 커서 추가 검증 필요 |
| `기각` | 성능·비용·실행·라이선스 중 하나 이상이 기준 미달 |

## 재현성

- 난수 시드, 데이터 SHA-256, 학습 인자, 코드 커밋을 보고서에 남깁니다.
- 생성된 가중치는 원본 파일과 변환 결과의 SHA-256을 함께 기록합니다.
- 보고서의 숫자는 가능한 한 저장된 JSON 결과에서 자동 생성합니다.
- 수동으로 옮긴 표는 원본 JSON 경로를 함께 적습니다.
